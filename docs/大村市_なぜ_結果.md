# 大村市の転入超過は、なぜ大きいのか — 結果

作成日 2026-10-14。設計: `docs/大村市_なぜ_設計.md`(固定。タグ `omura-why-design-v1`)。イベント: `ledger/omura_events.csv`(タグ `omura-why-events-v1`)。
コード: `src/nagplat/omura.py`(`python -m nagplat.cli omura`)。出力: `outputs/public/omura_*.csv`、`omura_yearly.png`。
区分: 「実測」= このパネルの値、「未確認」「未検証」。**1市の記述であり、原因を示すものではない。**

> **読む前に(3点)**
> 1. **「なぜ」の答えは出ていません。** 子育て・世帯数・出生数が「大村市の値と整合する」ことは、これらが転入超過の**原因**だったことを意味しません。人が転入してきた**結果**でも、同じ値になります。住宅(価格・供給)・交通・所得・転入元は、指標が無く、判断できていません。
> 2. **対象の市を、結果(目立つ市)を見てから選びました。** 転入超過が大きい市を、あとから選んだ偏りがあり、1市の事例で、他の市に一般化できません(設計 §0)。
> 3. **タグ `omura-why-code-v1` が指すコードは、バグのある版です**(国勢調査の年の取り違え)。修正は、その後のコミットにあります。結果の数値は、修正後のコードによるものです(§5)。

## 1. 結論(先に)
- **前提は成り立つ**: 2016〜2024年の9年とも、大村市の転入超過率は、県内の市の中央値と、全国の同規模の市(C2)の中央値の、両方より大きい(9/9年)。
- **差は、観測の最初の年(2016年)からある**。「いつ差が開いたか」は、2016年より前のデータが無いため、**判断できない**。
- **差の中身は、転入率の高さ**: 転入率は、C2の中央値の約1.7〜2.0倍(47〜53‰ 対 26〜28‰)。転出率も約1.4〜1.6倍と高く(42〜47‰ 対 28〜30‰)、転入超過は、2つの大きな流れの小さな差。
- **「なぜ」への答えは、このデータでは出せない**。手元の指標で「整合する」のは、子育て世帯・世帯数の増加・出生数の多さ。ただしこれらは、**人が転入してきた結果でもある**(逆の因果)。住宅・交通・所得・転入元は、手元に指標が無く、判断できない。
- **2024年に、差が急に広がった**(差 +14.2‰。2016〜2023年は +5.8〜+8.3‰)。原因は、このデータでは分からない。

## 4. 感度分析(別枠。結論にしない。`omura_sensitivity.csv`)
- 比較群: S1 規模の幅0.5〜2.0倍(230市)、S2 三大都市圏を含む全国(234市)、S3 九州・沖縄(30市)、S4 2015年の値が近い20市、S5 避難指示区域の候補を除く(**主と同じ126市。C2に候補が入っていなかったため、結果は同じ**)。
- 前提(9/9年)と、差が2016年から正であることは、全ての比較群で同じ。差の平均: 主 +7.8‰、S1 +8.1、S2 +7.1、S3 +7.0、S4 +4.6。
- 判定が**全ての比較群で同じ**指標: 支持 = I5a・I5b・I5d。合わない = I3a・I3b。判断できない = I3d。
- 判定が**比較群で変わる**指標: I1a(S4で判断できない)、I1b(S3で判断できない)、I3c(S3・S4で判断できない)、I5c(S2・S4で判断できない)、I6a(S1・S4で判断できない)、I6b(S2で合わない)、I7(S4で判断できない)。**これらの判定は、比較群の選び方に依存する**。
- 2015年の値が近い20市(S4)に絞ると、差の平均は小さくなり(+4.6‰)、「総回転率が高い」は支持されなくなる。

## 5. 正直な記録(手順)
1. 設計(§0の記録どおり、大村市の値は見ていなかった)→ イベントの一次資料の確認(`ledger/omura_events.csv`)→ コードの固定(`omura-why-code-v1`)→ 実行、の順。
2. **最初の実行に取り違えのバグがあった**: パネルの国勢調査の項目は、「年tの行にt−1年の調査」を持つ(2020年調査の値は2021年の行)。最初は、2020年の行(= 2015年調査の値)を「2020年」として使っていた。最初の実行の結果(I1aの世帯数の増加率が1.0など)で気づいた。修正は、設計(「2020年の値」)のとおりにするもので、結果の都合では選んでいない。修正と併せて、取り違えを防ぐテストを加えた(`tests/test_omura.py`)。
   - 修正前後で、判定が変わった指標: I1a(判断できない→支持)、I3d(合わない→判断できない)、I6a(判断できない→合わない)。他は同じ。
   - 修正後のコードは、タグ `omura-why-code-v1` の後のコミット。タグが指すコードは、バグのある版。
3. **設計の変更は、していない**。仮説・指標・比較群・判定の規則は、固定したとおり。結果を見てから足した指標は、無い。

## 6. 限界
- **1市の事例**で、結果に基づいて選んだ対象(§0)。他の市への一般化は、できない。
- **因果は示していない**。指標の方向は私が事前に決めたもので、根拠は弱い。「支持」は、整合の意味。
- 比較群の区間は、1市の値に対する、比較群の分布。大村市自身の不確かさは表していない。年の相関も考えていない。
- パネルに無い要因(住宅価格・地価・着工、所得、交通の利便、企業・公的機関の立地、転入元)は、**判断できない**。取得しての確認は、未実施。
- 分母が古い(2015年・2020年の国勢調査。年ごとの実際の人口ではない)。日本人移動者のみ。
- 事業所数・従業者数は、2021年の単年。従業地ベースの値を、常住の人口で割っている(通勤の影響を含む)。
- 年次項目の年の付け方(パネルの年と、実際の調査の年のずれ)は、台帳(`ledger/panel_items.csv`)のとおり。個別の確認は、未実施。
- 三大都市圏の区分は、本調査の定義(総務省の公式の区分との照合は、未確認)。
