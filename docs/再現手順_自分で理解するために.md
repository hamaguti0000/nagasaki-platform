# 自分で再現して理解するための手順(1ページ)

目的: `make` の順番に実行し、各段階の**出力のどこを見ればよいか**を知る。所要: 初回 約15分(取得 約8分 + テスト 約2分 + 確認)。
(この手順は、私は実行していない箇所を含む。各段階の「見る点」は、私の実行結果に基づく。あなたの環境での再現は**未検証**。)

## 0. 準備
```bash
cd nagasaki_platform
pip install -r requirements.txt     # 仮想環境を推奨(Python 3.12で確認)。ここでは .pylibs に入っている
```
読む順番(コード): `src/nagplat/common.py` → `fetch.py` → `parse_kanko.py`・`parse_jinko.py`・`parse_jma.py`・`parse_boundary.py` → `build.py` → `validate.py` → `mapmaker.py` → `tests/test_pipeline.py`

## 1. `make fetch` — 取得(初回 約8分)
| 見るもの | 期待する出力 | 理解すること |
|---|---|---|
| 端末 | `fetch: fetched=N skipped(already verified)=0 problems=0` | 全て取得できた。問題0 |
| `manifest/fetch_log.csv` | 1行=1ファイル。`result` が全て `fetched` | URL・HTTP・容量・SHA256・日時の記録 |
| `config/sources.csv` | `expected_sha256` が入っている行 | 県の原本は、期待ハッシュと不一致なら保存しない |
| 2回目の `make fetch` | `fetched=0 skipped=全部` | 取得済みで一致するものは、再取得しない(外部アクセスなし) |

## 2. `make verify-raw` — 原本の確認
- 期待: `raw verify: OK`。見る点: `raw/` のファイルのハッシュが、記録と一致していること。

## 3. `make build` — 蓄積(私の環境で約101秒)
| 見るもの | 理解すること |
|---|---|
| 端末 `build: OK` | bronze → silver → gold が作られた |
| `data/public/bronze/`, `silver/`, `gold/` | 国・気象庁のデータ(公開可)。`data/restricted/` は県統計由来(公開しない) |
| `data/public/gold/gold_station_year.csv` | 観測点×年の気温・降水量・日照。空欄の行は資料不足値を含む年(`n_excluded_values`) |
| `ledger/comparability_flags.csv` | 県の「算定方法の見直し」から導いた比較不可フラグ(39行) |
| `ledger/source_measurements.csv` | ソースごとの実測の容量・行数 |
| `manifest/output_hashes.csv` | 出力のハッシュ(再実行で変わらないこと) |

## 4. `make validate` — 検証(私の環境で約1秒。PDFのテキストは初回のみ抽出)
- 期待: `validate: 30 checks, FAIL=0, WARN=2`。結果は `ledger/validation_results.csv`。
- 見る点:
  - `V30` 観光客延べ数 = 日帰り+宿泊、`V32` 人口増減 = 社会増減+自然増減、`V31`/`V35` 県計 = 市町の合計。
  - `V50`〜`V52` 県の注記(再算定)と、赤字のセルの整合。
  - `V24`(WARN) 気象庁の記号つきの月が54件。`V53`(WARN) 2015年版PDFは文字を取り出せず未検証。
- 理解すること: **FAIL があると地図は作らない**。WARN は、許容して記録しているもの。

## 5. `make map` — 地図(私の環境で約5秒)
| 見るもの | 理解すること |
|---|---|
| `outputs/public/map_population_2020_weather_2025.png` | 公開してよい地図。下端に出典・加工の注記 |
| `outputs/restricted/map_tourists_per_capita_2025.png` | 県統計由来(公開しない) |
| `outputs/*/*.lineage.json` | 系譜: どのソース(URL・SHA256)から作ったか。コードのハッシュ、ライブラリの版 |

## 6. `make test` — テスト(約2分)
- 期待: `19 passed`。見る点: 最後の `test_rebuild_is_deterministic` が、ビルドを2回行って出力のハッシュが一致することを確認している(時間がかかる理由)。

## 7. その他のコマンド
| コマンド | 目的 | 見る点 |
|---|---|---|
| `make privacy-scan` | 公開対象に個人情報がないか | `hits=0`。`publish/PRIVACY_SCAN.md` |
| `make qc-report` | 気象庁の記号の集計 | `ledger/weather_qc_flags.csv`(90値・54か月) |
| `make notice` | NOTICE の再生成 | 規約の引用が、取得したページと逐語一致 |
| `make publish-list` | 公開用・非公開用の一覧 | `publish/PUBLISH_LIST.md` |
| `make all` | build → validate → map | FAIL があれば途中で止まる |
| `make clean` | `warehouse/ data/ outputs/ work/` を削除 | `raw/` と台帳は消えない。`make all` で再生成 |

## 8. 自分で壊して確かめる(理解を深める。コピーの上で行う)
1. `raw/` の1ファイルを別名にする → `make verify-raw` が `missing ...` で失敗する(取得の防御)。
2. `config/expected_counts.csv` の数値を1つ変える → `make validate` で `V10:...` が FAIL になり、`make all` が地図の前で止まる。
3. `src/nagplat/build.py` の `SET threads TO 1` を外して `make test` → 再現性のテストが落ちる可能性がある(落ちるかは**未検証**)。
