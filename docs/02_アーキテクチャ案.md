## 全体像
```
 取得(fetch)        蓄積(store)          検証(validate)       分析・予測(model)     可視化(serve)
 ─────────────      ─────────────        ──────────────       ─────────────────     ──────────────
 API / ダウンロード  raw/ (原本そのまま)  SQLテスト+台帳照合    特徴量 → 予測         Parquet/CSV 出力
  + 取得ログ(SHA256)  → bronze (Parquet)   → 失敗なら停止        → 検証(過去で試す)    → Power BI (地図+表)
                      → silver (整形)                                                → 静的地図(公開用)
                      → gold (指標)
                  └────────────── DuckDB (1ファイル) + SQL ──────────────┘
                  └──────────── 台帳(ledger): 版・再算定・比較不可・取得ログ ───────────┘
```

## 層の役割
| 層 | 中身 | ルール |
|---|---|---|
| raw | 提供元の原本(xls/xlsx/zip/json)。**書き換えない** | 取得ログ(URL・HTTP・サイズ・SHA256・取得日)を `SOURCES.csv` に追記(既存フォルダーと同じ考え方) |
| bronze | 原本を、列名・型を変えずにParquet化 | 1ソース1ディレクトリ、取得日でパーティション |
| silver | 市町コード・年月・単位を揃えた長い形式 | 市町は**名称ではなく団体コード**で持つ。単位は列名に入れる |
| gold | 指標(人口あたり観光客、前年同月比、メッシュ人口など) | 指標の定義を1か所(SQLのビュー)に置く |
| ledger | 版・再算定・比較不可・検証結果 | 下記 |

## 技術選定(案と理由)
| 項目 | 案 | 理由 | 代替 |
|---|---|---|---|
| 保存・SQL | DuckDB + Parquet | サーバー不要・1ファイル。個人で動かせる。Parquetは Power BI が読める(未検証) | SQLite(空間機能が弱い)。PostgreSQL+PostGIS(運用が重い) |
| 空間処理 | DuckDB spatial 拡張 or GeoPandas | メッシュ×市町×停留所の結合に必要 | 未検証。拡張の可用性は実装時に確認 |
| 取得・整形 | Python(requests, pandas/pyarrow) | 既存フォルダーのスクリプトと同じ言語 | |
| SQL変換 | 素のSQLファイル。必要ならdbt-duckdb | テストと依存関係を管理したくなった時点で導入 | 最初から入れない |
| 検証 | SQLの検査(0行ならOK)+Pythonのテスト | 依存を増やさない | pandera、Great Expectations |
| 環境固定 | uv/pip の lockfile、Pythonのバージョン固定 | 再現性 | Docker(重い) |
| 自動実行 | GitHub Actions(schedule + workflow_dispatch) | ポートフォリオで見える | ローカルcron |
| 可視化 | Power BI(Parquet/CSV読み込み)+ 公開用の静的地図(HTML/PNG) | Power BIは受託の窓口。公開用は別に持つ(Webに公開の制約は別フォルダーの設計案に記録) | |

## 自動更新(GitHub Actions)
- **頻度はソースごとに分ける**: 月次(観光施設・人口)、四半期(不動産)、年次(統計・GTFSは変更検知)。毎日回す意味はない。
- **変更検知**: 取得前に提供元ページの更新日・ファイルサイズ・SHA256を比べ、変化がなければ何もしない。変化があれば取得し、**新しい版として追加**(上書きしない)。
- **失敗時**: 取得失敗・検証失敗では公開物を更新しない。ログに残し、Issue化(通知)。
- **秘密情報**: e-Stat の appId、不動産情報ライブラリの APIキーは Actions の Secrets。リポジトリに入れない(APIキーは第三者に公開不可。原文は01の#8)。
- **原本の置き場**: 提供元の許諾が確認できるまで、**原本とbronzeはリポジトリに入れない**(Actionsのキャッシュ/アーティファクト)。リポジトリには、スクリプト・SQL・マニフェスト(SHA256付き)・台帳・**ライセンス確認済みの集計値**だけを置く。
- **未検証の点**: Actionsの実行時間・ストレージの上限、公開リポジトリで一定期間活動がないとスケジュールが止まる仕様の有無(私の知識では止まるが、公式文面は未確認)。

## 再現性の確保
1. **原本のSHA256を固定**: マニフェストにあるハッシュと一致しない原本は使わない。
2. **同じ入力 → 同じ出力**: 全変換は決定的に(乱数は seed 固定、並び順を指定)。出力のハッシュをCIで比較。
3. **版の管理**: 「いつ取得した、どの版の値か」を全行に持つ(`source_version`、`fetched_at`)。
4. **1コマンドで再生成**: `make all`(または同等)で、raw取得済みの状態から gold まで再生成。
5. **予測の再現**: 学習期間・特徴量・seed・ライブラリ版を実行記録に保存。

## 品質管理: 台帳(ledger)
nagasaki_kanko_v2 の台帳(シート: 取得状況/ソース一覧/再算定・注記/比較不可フラグ/推計人口の基準/市町構成/検証結果/不一致一覧/未取得・未検証)の考え方に沿う。**ファイルはコピーしない**。ここでは、機械で扱える表(Parquet/CSV)として設計する。

| 台帳の表 | 役割 | 主な列(案) |
|---|---|---|
| `source_registry` | ソース台帳(01の機械可読版) | source_id, 名称, 提供元, URL, 形式, 更新頻度, 利用条件(原文), 条件の確認日, 私の解釈, 公開可否(raw/derived) |
| `fetch_log` | 取得ログ | source_id, URL, HTTP, bytes, sha256, fetched_at, 提供元の更新日 |
| `revision_log` | 再算定・改定の記録 | series_id, 期間, 市町コード, 値(旧), 値(新), 旧版, 新版, 差, 理由(提供元の注記の原文) |
| `comparability_flags` | **比較不可フラグ**(算定方法の見直し・観測点移設・施設の追加休止・境界変更) | series_id, 市町/施設, 開始, 終了, 種類, 根拠(原文), 比べてよい範囲 |
| `area_master` | 市町の団体コード・名称・合併・境界の履歴 | code, 名称, 有効期間, 前身 |
| `validation_results` | 検証の結果(実行ごと) | run_id, check_id, 対象, 合否, 値, 閾値 |
| `open_issues` | 未確認・未検証の一覧 | id, 内容, 影響, 確認方法 |

**運用ルール**
- 指標を出す時、採用した版とフラグを必ず結合する。**比較不可の期間をまたぐ前年比は計算せず、注記を付ける**。
- 提供元が値を改定した時は、上書きせず `revision_log` に残す(例: 施設の月次値は6,000件中208件が後年の版で変わった。別フォルダーの記録)。
- 検証の失敗は、公開物の更新を止める。

## 標準の検証(例。閾値は実装時に決める)
- 市町の網羅: 21市町+県計が、各年で欠けていない。
- 合計の整合: 市町の合計 = 県計(既存フォルダーの観光統計は、県の集約表と全件一致を確認済み)。
- 人口の連続: 期末(翌年1月1日) = 翌年の期首、または差が「国勢調査補正等」で説明できる。
- 範囲: 負の人数、前年比が極端な値(閾値は未定)を検出し、台帳の注記と照合。
- 空間: メッシュ人口の合計と、市町人口の差(境界・秘匿処理による差は未確認)。
